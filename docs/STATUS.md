# 検証結果 0.2.1

## 確認済み

- 0.2.1ではクライアントID・シークレットの直接入力を追加。JSONがなくてもWindows上のローカル画面で入力可能。型検査・ビルド成功。
- Google実アカウントで初回認証が成功し、認可コード交換後の「認証できました」表示を確認。秘密の値をチャット・ログ・配布物には含めていない。iPhone取込と実ファイル同期は未確認。

- npm run build：strict型検査、main.jsとgoogle-auth-helper.mjsの生成に成功。
- npm test：39件成功、失敗0、スキップ0。同期・設定安全性21件、ローカル認証ツール3件、暗号化取込4件、スケジューラ4件、通信・Drive・認証7件。
- PKCEとstate、callback再利用拒否、同一Origin制限、localhost実HTTP、Googleエラー秘匿、暗号化設定改ざん・期限・コード違いを試験。
- Google確認失敗時は旧接続を保持。保存はSecretStorageだけ、access tokenはメモリ。refreshの重複抑止、解除時のローカル保存値消去も試験。
- ソース・依存から中継コードとCloudflare用依存を削除。WindowsツールはNode標準APIのみ。
- ビルド済み認証ツールをWindowsで起動し、ブラウザで日本語の接続準備画面・JSON選択・権限選択・認証開始ボタンの表示を確認。Google認証は行っていない。試験後ツールを終了。
- 実保管庫・実Googleアカウントを初期試験には使っていない。

## 未検証・制限

1. Google初回OAuthの成功は確認済み。iPhoneへの引継ぎと実refreshは未確認。初回認証合格を同期全体の合格に置き換えない。
2. Driveへの実ファイル転送と条件付きmedia PATCH：未実施。古いETagが412で拒否されるか試験必須。ETag欠如では上書きを停止。複数ライターの厳密な無損失保証は未達。
3. iOSプラグイン手動導入、実Vault動作、画面ロック復帰：未実施。
4. Windows Drive for desktop、Hermes、ChatGPT本文取得：未実施。通常.md構造と手順だけ用意。ChatGPTが本文を取得できなければ別コピーの.txt添付等を使用。
5. 既存バイナリのリモート変更：原子的置換ができないため競合コピーで受信。
6. drive.fileでの外部新規ファイル可視性：仕様上制限。必要なら認証時にdrive全体の権限を明示選択。
7. 暗号化設定は10分以内に取込可能だが、サーバーで一回使用を強制しない。コードと設定が両方漏れた場合はGoogleで失効する。
8. 未実装：Changes API最適化、分散ロック、共有ドライブ、Docs形式、ショートカット、空フォルダ単体、削除伝播、履歴の自動容量整理、ChatGPT自動取込、ストア公開。
