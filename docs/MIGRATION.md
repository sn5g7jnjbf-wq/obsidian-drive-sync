# 既存iCloud保管庫からの安全な移行

1. **元の保管庫では試験しない。** 小さなテスト保管庫で、認証・アップロード・ダウンロード・競合・再起動・復旧の試験を先に行います。ETagの古い版拒否が確認できない場合は移行しません。
2. すべての端末で編集を止め、iCloudが全ファイルをダウンロードし終えるのを待ちます。添付ファイルも端末から実際に開けることを確認します。雲アイコンのプレースホルダーを完全なバックアップと扱いません。
3. iCloud保管庫全体を別の安全な場所へコピー／ZIP保存。ノート数・添付数・代表ファイル本文を確認します。できればWindows側等にも独立した世代バックアップを保管します。
4. iPhoneのObsidianで「このiPhone内」に新規のローカル保管庫を作り、元のコピーをそこへ入れます。元のiCloud保管庫はそのまま残し、以後編集しません。iCloudの設定をOFFにするだけでデータが必ず移動するとは考えないでください。
5. コピー先に本プラグインを導入し、認証。空の専用Driveフォルダを新規作成します。既存の大きなDriveフォルダに直接初回同期しないでください。
6. コピー先にほかの同期プラグインが残っていたら無効化。Obsidian Sync、iCloud、本プラグインを同一実体へ同時に走らせると、競合・リネーム・削除判断が循環するため避けます。
7. 容量上限を確認します。既定では1MB以上の添付を送らないので、全件同期と誤認しないでください。除外ファイル一覧を記録し、必要に応じ上限を調整します。iOSのメモリ制限を考慮し、一度に100MBの転送を前提にしません。
8. バックアップ確認をONにして手動同期。ノート総数、サブフォルダ、代表ノートの本文と日本語名、添付、リンクをDrive WebとWindows側で確認します。ドットパス・履歴領域は対象外です。空フォルダだけは転送されません。
9. iPhone・Windows双方でテスト用ノートだけを更新して往復確認。競合コピーの確認方法、上書き前履歴の復元方法を練習します。`drive.file`の場合はWindows新規ファイルが見えない権限制限を確認します。
10. 合格後に自動同期をON。しばらく元のiCloud保管庫を読取用バックアップとして保存し、安定稼働を確認してから整理します。元の削除はこのプラグインでは実行しません。

## 復元と撤退

異常時は自動同期をOFF、同期終了を待ち、両側の現状を別々にバックアップします。履歴から必要な版を別名でコピーして内容を確認し、正しい内容を手動で原本へ反映します。競合を「どちらかを削除すれば同期される」と考えないでください。削除は伝播しません。

元のiCloudへ戻す場合は、独自同期を完全に止め、元と移行先の差分を手動で統合してから編集を再開します。双方向の自動同期を有効にしたまま保管庫を入れ替えないでください。
