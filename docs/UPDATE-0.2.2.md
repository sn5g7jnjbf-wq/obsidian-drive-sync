# 0.2.2：Windowsで新しく作ったノートを取得する

原因は従来の drive.file 権限です。プラグインが作ったファイル以外は一覧に出ないため、Windows新規ノートがあっても同期完了と表示されていました。

## いまの保管庫を維持して更新

1. iPadの保管庫を別の場所へコピーしてバックアップします。自動同期を一時OFFにします。
2. Obsidianの設定でDrive SyncをOFFにします。
3. 配布ZIPの `obsidian-ai-drive-sync` フォルダにある `main.js` と `manifest.json` を、いま使っている保管庫の `.obsidian/plugins/obsidian-ai-drive-sync/` に上書きします。既存の `data.json` や保管庫を削除しないでください。新しい保管庫を作る必要もありません。
4. プラグインをONにし、バージョンが0.2.2であることを確認します。

## 再認証（必須）

1. Windowsで同梱の `Start-Auth.cmd` を実行します。Node.js 22以上が必要です。
2. 既存のデスクトップOAuthクライアントのIDとシークレットを入力します。Google Cloudのクライアントを作り直す必要はありません。
3. 権限は初期選択の「推奨：Windowsで新規作成したノートも双方向同期」のまま進めます。
4. Googleの画面でDrive全体の読み書きを許可します。必要ならGoogle CloudのGoogle Auth Platform → データアクセスで `https://www.googleapis.com/auth/drive` を追加します。ブロックされた場合はその表示を確認し、組織の制限を回避しないでください。
5. 認証後に表示される新しい「暗号化した接続設定」と「解除コード」を、10分以内にiPadのDrive Sync →「Windowsの接続設定を取り込む」に入力します。チャットに認証情報を貼らないでください。
6. **接続解除は不要です。同期先は以前と同じフォルダIDを維持してください。「新しい専用フォルダ」は作成しません。**
7. 「許可したDrive権限」が「Windows新規ファイル対応」になったら「今すぐ同期」を押します。

プラグイン更新だけではGoogleの権限は増えません。古い権限のままなら同期結果にも警告が出ます。

## 確認

Windowsで同期先直下に `Windows-test.md` を新規作成 → ブラウザー版Driveで内容を確認 → iPadで手動同期 → ノートが現れることを確認します。その後iPadで追記 → 同期 → Windowsで確認してください。同名の別内容がある場合は競合コピーになり、自動上書きしません。

## 権限と検証の範囲

Drive全体の読み取りだけでは、Windows作成ファイルへの変更の書き戻しができないため、双方向同期にはDrive全体の読み書きを使います。Googleの権限はフォルダ限定ではありません。プラグインの同期処理は選んだフォルダ内に限定し、自動削除は行いません。認証情報が漏れた場合の影響範囲は大きくなります。

公式仕様：https://developers.google.com/workspace/drive/api/guides/api-specific-auth

この修正版は型検査・ビルド・モックを使った自動テストで検証しています。ユーザーのiPadとGoogle実アカウントでの再認証・往復同期は、この手順で別途確認が必要です。公開配布ではrestricted scopeの審査要件を確認してください。個人のTesting利用では更新トークンの期限が通常7日になる制約は残ります。
