# Drive Sync — experimental 0.2.4

Obsidianの保管庫をGoogle Driveの通常ファイルとして同期する、TypeScript製の実験版プラグインです。iPhone・iPad向けに設計し、Windowsでも動作可能な構成です。Markdownと添付ファイルの階層を維持し、Windowsから通常のファイルとして参照・編集できる形式を使います。AI処理やAIサービスへの送信機能はありません。

**実験版です。最初はバックアップ済みのテスト保管庫で利用してください。** 利用者の実機環境で同期の成功報告があります。Windowsから反映されなかった事例は、Google Drive for desktopのアップロードが完了していなかったことが原因で、反映完了後に解決しました。この事例をプラグインの未解決不具合としては扱いません。競合・障害復旧などの網羅的な実機検証は別途必要です。

## 他の人が使うには

各利用者が自分のGoogle CloudプロジェクトとデスクトップOAuthクライアントを作成します。作者のクライアント情報・トークン・保管庫を配布する方式ではありません。Googleの認証画面を開くため、初回だけWindowsとNode.js 22以上が必要です。認証後のプラグイン通信はGoogleへ直接接続し、独自認証サーバーは使いません。

1. GitHub Releasesが公開されたら、その配布ファイルを使用します。ソースZIPだけではビルドが必要です。
2. [導入手順](docs/INSTALL.md)に沿って、実データのないテスト保管庫へ導入します。
3. [Google Cloud設定](docs/OAUTH.md)を行い、Windowsで同梱のStart-Auth.cmdを起動します。
4. Windowsの新規ノートも対象にする場合は、認証ツールの「推奨」を選びます。GoogleのDrive全体の読み書き権限を確認してください。OAuthの権限自体はフォルダ限定ではありませんが、同期処理は選んだフォルダ内のみです。
5. 表示された接続設定と解除コードを10分以内にモバイル側へ取り込み、同期先とバックアップ確認を設定します。認証情報はチャットやGitHubに貼らないでください。
6. ノート1枚で追加・変更・競合を確認してから自動同期を有効化します。Windowsでは、ブラウザー版Driveに本文が届いていることも確認します。

公式コミュニティプラグイン一覧には未登録です。iOS標準「ファイル」アプリに隠しフォルダ表示メニューがあるとは案内しません。手動導入で設定フォルダを操作できない場合の方法と、今後の導入改善は[導入手順](docs/INSTALL.md)を確認してください。

## 機能

- ローカルSHA-256とDrive versionによる差分転送。
- 初回の同名異内容や両側変更では競合コピーを作り、原本を維持。
- 自動削除なし。追跡済みファイルの片側消失は保留。
- 自動同期と起動時同期は初期OFF。間隔1分、起動待機1秒、容量上限1MB。
- 容量上限以上のファイルは除外し、既存のクラウドファイルを削除しません。
- 履歴と競合コピーは保管庫内のAI Drive Syncフォルダに保存し、同期から除外。
- 認証情報はObsidian SecretStorageへ保存。アクセストークンはメモリのみ。
- 診断表示にはファイル名が含まれます。公開Issueに載せる前に個人情報を伏せてください。

## 制限

- Windows認証ツールからモバイルへ認証情報を移す方式は、GoogleがObsidian向けに公式保証した連携方式ではありません。
- Google CloudのExternal/Testingでは更新トークンが通常7日で失効します。長期運用・公開配布の認証要件は[認証の説明](docs/OAUTH.md)を確認してください。
- 制限付きdrive.file権限では、Windowsで新規作成した任意のファイルは取得できません。権限変更には再認証が必要です。
- 既存ファイルのDrive上書きにはETagを要求します。Google実APIでの条件付き更新は未検証で、ETagを取得できなければ安全のため停止します。
- iOSバックグラウンド動作、共有ドライブ、Google Docs形式、ショートカット、空フォルダ単体、分散ロックは未対応です。
- 同じ実フォルダへDrive for desktopとプラグインを同時に書き込ませないでください。iCloud同期との二重運用も避けてください。
- Windowsや外部アプリからの参照方法は[外部アプリでの利用](docs/EXTERNAL-APPS.md)を参照してください。

## 開発と配布

Node.js 22以上で npm ci → npm run build → npm test を実行します。Node.js専用APIは認証ツール・開発処理だけで使い、プラグイン本体には使いません。

GitHub Actionsで型検査・ビルド・テストと成果物の作成を行います。manifest.jsonと一致する0.x.xタグをpushすると、実験版のPrereleaseを作ります。main.jsとmanifest.jsonをReleaseの個別添付ファイルとして配布します。これらはObsidian公式の配布形式です。

## 旧名との互換性

旧表示名はAI Drive Syncです。0.2.4からDrive Syncに変更しました。既存の設定・認証・履歴を引き継ぐため、内部プラグインID `obsidian-ai-drive-sync`、暗号化形式、既存の履歴保存先 `AI Drive Sync/` は維持しています。フォルダを手動で改名する必要はありません。新規作成するDriveフォルダ名はDrive Sync Vaultです。
